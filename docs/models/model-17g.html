Supplementary analytical sketch

17g financial record class model

Source-only analytical sketch. This model is exploratory and is not evidence of an operational interface or a universal government process. It is retained for analysis, not substituted for a diagram that answers a narrower question.

Notation: PlantUML · Get source code

Source

' QUESTION THIS DIAGRAM ANSWERS: How can many-to-many references be represented without treating UACS as a transaction key?
' SOURCES: Proposed logical schema; technical field contracts require verification
' GENERAL KNOWLEDGE / conceptual schema; not statutory structure
@startuml
title 17g Typed financial records with stable IDs and versioned classification
skinparam shadowing false
hide methods
class Authority {
  id
  issuer
  effective_interval
}
class Rule {
  rule_id
  scope
  validity_start
  validity_end
}
class Event {
  event_id
  event_type
  occurred_at
  fiscal_year
  amount
  currency
  jurisdiction
}
class Record {
  record_id
  record_type
  authority_owner
  version
  issued_at
}
class EventRecordLink {
  role
  relationship
  valid_from
  evidence_id
}
class Classification {
  taxonomy
  code
  version
  effective_date
}
class ClassificationAssignment {
  assignment_id
  applied_date
  mapping_basis
}
class Application {
  system_id
  owner
  environment
  deployment_status
}
class Exchange {
  exchange_id
  mechanism
  evidence_level
  observed_at
}
class Balance {
  kind
  currency
  as_of
  source_record_id
}
Authority "1" --> "0..*" Event : authorizes / acts
Rule "0..*" --> "0..*" Event : constrains
Event "1" -- "0..*" EventRecordLink
Record "1" -- "0..*" EventRecordLink
Record "1" -- "0..*" ClassificationAssignment
Classification "1" -- "0..*" ClassificationAssignment
Event "0..*" --> "0..*" Balance : changes / explains
Application "0..*" --> "0..*" Record : contains copy / original
Application "1" --> "0..*" Exchange : origin
Exchange "0..*" --> "1" Application : destination
@enduml
